# Задача: crash-safe компактор журнала

В `journal.py` — заготовки `append_event` и `compact`. Это журнал доставки
задач: процесс может быть убит В ЛЮБОЙ момент (kill -9 посреди любого
сисколла записи), и после рестарта данные обязаны читаться без потерь
подтверждённого. Реализуй по контракту.

## Формат и контракт

Журнал — файл `journal.log`, по строке JSON на событие:
`{"seq": int, "op": "set"|"del", "key": str, "value": str|null}`
(`value` присутствует только у `set`). `seq` строго возрастает с 1 без
пропусков в ПОДТВЕРЖДЁННОЙ части.

- `append_event(dir_path, op, key, value=None) -> int` — дописать событие со
  следующим seq и вернуть его. Подтверждённым событие считается после
  возврата функции: вернувшийся seq обязан пережить kill -9 сразу после
  возврата (думай про flush и os.fsync). Незавершённый хвост (оборванная
  последняя строка от убитого посреди записи процесса) при следующем
  append обнаруживается и обрезается, seq продолжается от последней ЦЕЛОЙ
  строки.
- `read_state(dir_path) -> dict` — свернуть журнал в состояние
  {key: value}: применить события по порядку seq (set кладёт, del удаляет).
  Оборванная последняя строка игнорируется. Дубликат seq (одинаковый номер
  дважды — след двойного ретрая) применяется один раз, первым вхождением.
  Пропуск seq в середине ЦЕЛЫХ строк — повреждение: RuntimeError.
- `compact(dir_path) -> None` — заменить журнал на минимальный эквивалент:
  по одному `set` на каждый живой ключ (отсортировано по ключу), с
  ПЕРЕНУМЕРАЦИЕЙ seq с 1, и продолжить следующие append от нового максимума.
  Компакция обязана быть атомарной к kill -9 В ЛЮБОЙ её точке: после
  рестарта read_state видит либо полностью старый журнал, либо полностью
  новый — никогда смесь, никогда пустоту (при непустом состоянии).
  Думай про запись во временный файл, fsync файла, os.replace и fsync
  КАТАЛОГА. Повторная компакция уже компактного журнала — no-op без потерь.

Крайние случаи, которые обязаны работать: пустой каталог (read_state -> {},
первый append -> seq 1); журнал из одного оборванного хвоста; del
несуществующего ключа (валиден, состояние не меняет); значения с
переводами строк ВНУТРИ value (JSON это переживает — а твой парсер строк?);
ключ "" — валиден.
