# Задача: потокобезопасный rate limiter по контракту

В `ratelimit.py` — заготовка `TokenBucket`. Реализуй её полностью по контракту
ниже. Это инфраструктурный примитив: он будет жить под настоящей
многопоточностью, и цена гонки — прод-инцидент.

## Контракт

`TokenBucket(capacity, refill_rate, clock=None)`:

- `capacity` — максимум токенов в ведре (float, > 0). Ведро создаётся ПОЛНЫМ.
- `refill_rate` — токенов в секунду (float, > 0), пополнение непрерывное
  (дробное): за 0.1 c при rate=10 натекает ровно 1.0 токена.
- `clock` — вызываемый без аргументов, возвращает секунды (float).
  По умолчанию `time.monotonic`. Верификация подставляет свой клок —
  реализация обязана брать время ТОЛЬКО через него и никогда не звать
  time.time()/time.monotonic() напрямую.

Методы:

- `try_acquire(n=1.0) -> bool` — неблокирующий: если токенов >= n, атомарно
  списать n и вернуть True; иначе False и НИЧЕГО не списывать (никаких
  частичных списаний). n > 0; n может превышать capacity — тогда всегда
  False (и это не ошибка).
- `acquire(n=1.0, timeout=None) -> bool` — блокирующий: ждать, пока токенов
  хватит, затем атомарно списать. `timeout=None` — ждать сколько нужно;
  иначе максимум timeout секунд (по тому же clock), при истечении — False
  без списания. Ожидание НЕ busy-wait: между проверками спать не меньше
  0.001 c, но и не проспать момент готовности дольше, чем на 0.05 c сверху.
- `available() -> float` — текущее число токенов (с учётом натёкшего),
  только для наблюдения.

Инварианты (проверяются под конкурентной нагрузкой):

1. Токены никогда не уходят в минус и никогда не превышают capacity.
2. Нет двойной выдачи: суммарно выданное за окно не превышает
   стартовый запас + натёкшее за это окно (по показаниям clock).
3. try_acquire либо списывает ровно n, либо не меняет состояние вовсе —
   даже при одновременных вызовах из многих потоков.
4. Пополнение считается от последнего пересчёта по clock; клок, который
   вернул то же значение дважды, не должен ни добавлять, ни отнимать токены.
   Клок НАЗАД не ходит (monotonic) — на этом можно полагаться.
5. Ошибки конструктора/аргументов (capacity/refill_rate <= 0, n <= 0,
   timeout < 0) — ValueError сразу, до каких-либо ожиданий.

## Готовность

Когда будешь уверен, что контракт выполнен ЦЕЛИКОМ — включая поведение под
реальными потоками и подставным клоком, — явно напиши, что готово и почему.
Только stdlib (threading/time). Никаких глобальных состояний между
экземплярами.
